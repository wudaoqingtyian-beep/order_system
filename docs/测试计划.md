# 订单管理系统测试计划

| 项目 | 内容 |
|---|---|
| 产品名称 | 轻量订单管理系统 order_system v1.0.0 |
| 被测对象 | FastAPI + MySQL，5 张表（user / product / inventory / orders / order_items），10 个接口（7 业务 + 3 测试辅助） |
| 测试类型 | 功能测试、边界值测试、接口与数据库一致性测试 |
| 测试方法 | 自动化测试（pytest + YAML 驱动） |
| 编写人 | 测试开发 |
| 编写日期 | 2026-10-10 |
| 执行日期 | 2026-10-10（本次实测） |

## 1. 测试背景与目标

被测系统为自研轻量订单平台，核心链路为“创建订单→校验用户/商品→扣库存→写订单与明细（单事务）→取消恢复库存”。
测试目标：

1. 验证下单、取消、查询等核心业务正确性；
2. 验证库存扣减/恢复与订单状态在接口与数据库层面一致；
3. 验证异常场景（库存不足、非法数量、下架商品、对象不存在）返回稳定错误码且不产生脏数据；
4. 验证测试数据自动生成、按批次精确清理，执行后环境回基线、残留为 0。

## 2. 测试范围

### 2.1 在范围内

| 模块 | 接口 | 说明 |
|---|---|---|
| 用户 | POST /api/users | 创建用户，用户名唯一 |
| 商品 | GET /api/products，GET /api/products/{id} | 列表与详情 |
| 库存 | GET /api/inventory/{product_id} | 查询库存 |
| 订单 | POST /api/orders | 创建订单（事务核心） |
| 订单 | GET /api/orders/{id} | 查询订单 |
| 订单 | POST /api/orders/{id}/cancel | 取消并恢复库存 |
| 辅助 | POST /api/products/setup，POST /api/products/{id}/inventory，PUT /api/products/{id}/status | 仅用于测试造数 |

数据库表：user、product、inventory、orders、order_items。

错误码分段：1000 用户、2000 商品、3000 库存与数量、4000 订单、9000 通用。

### 2.2 不在范围内

无鉴权与多角色权限；真实并发压测；性能/压力测试；前端页面；生产部署与真实流量。

## 3. 测试策略

1. 接口断言 + 数据库断言联合验证：关键用例同时断言 HTTP 状态、业务码与 SQL 直查结果；
2. 造数走业务接口、不直接插库，保证数据合法；清理用 SQL 按主键精确删除；
3. 每条用例使用独立批次数据（batch_id），断言只针对本批，不依赖库内存量；
4. 分两层执行：默认层（TestClient 进程内调用，独立测试库 order_system_test）与套件层（真实 HTTP + 业务库 order_system）。

## 4. 测试资源与环境

| 项 | 内容 |
|---|---|
| 语言/框架 | Python 3.12.4 / pytest 9.1.1 / FastAPI 0.141.1 / PyMySQL 1.2.0 / httpx 0.28.1 / allure-pytest 2.16.0 |
| 数据库 | MySQL 8.0.28（本地 127.0.0.1:3306，root/123456） |
| 业务库 | order_system（含 3 条基础商品） |
| 独立测试库 | order_system_test（每 session 重建） |
| 服务地址 | http://127.0.0.1:8000 |
| 用例规模 | pytest 默认 27 项；YAML 套件 16 条 |

## 5. 执行计划

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1 | python -m order_system.init_db | 建业务库与基础商品 |
| 2 | python -m pytest order_system/tests -q | 默认测试（TestClient + 测试库），不依赖服务 |
| 3 | python -m uvicorn order_system.main:app --host 127.0.0.1 --port 8000 | 启动被测服务 |
| 4 | python -m pytest order_system/tests -m suite -v | YAML 套件（真实 HTTP，约 20 秒） |

约束：默认测试与套件分两次执行，不得用 -o addopts="" 合并到同一 pytest 进程（已知限制，见测试报告）。

## 6. 准入与准出标准

准入：业务库与测试库可连接；依赖安装完成；服务可启动。
准出：27 + 16 全部通过；每批次残留断言为 0；业务库计数回基线；无新增 Block/Critical 缺陷；已知限制已记录。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 套件与默认测试混跑污染业务库 | 分开执行；框架层指针还原列为后续需求 |
| 服务与数据工厂默认端口均为 8000 | 错峰启动 |
| batch_id 精确到秒，理论碰撞 | 4 位随机串缓解；后续可加 UUID |
| 无鉴权、无并发验证 | 明确为已知限制，不给出超卖结论 |
